2. S7: Embedding Alignment Analysis

2.1 What is Doc-Cosine?

Metric Doc-Cosine (document alignment cosine) measures how close a student's document embedding is to the teacher's document embedding for the same code snippet.

Definition — Per-example Doc-Cosine $$\text{doc\_cosine}(i) = \cos\!\bigl(\mathbf{s}_i,\;\mathbf{t}_i\bigr) = \frac{\mathbf{s}_i \cdot \mathbf{t}_i}{\|\mathbf{s}_i\|\;\|\mathbf{t}_i\|}$$

where for each test code example $c_i$:

  • $\mathbf{s}_i = f_{\theta}^{\text{student}}(c_i) \in \mathbb{R}^{312}$ — student document embedding
  • $\mathbf{t}_i = f_{\phi}^{\text{teacher}}(c_i) \in \mathbb{R}^{384}$ — fine-tuned teacher document embedding (projected to shared space)
  • Range: $[-1, +1]$. Higher = student embedding points in the same direction as teacher.
Why it matters: In symmetric retrieval the student encodes both the query and the code document. If the student's document embeddings diverge from the teacher's, the student's ranking degrades. Doc-cosine directly measures this risk.

2.5 Why Score Distill & Hard Neg Pairwise Are Excluded

Their losses are rotation-invariant: they operate on dot-product scores, not on the embedding vectors themselves.

Score Distill Loss (rotation-invariant) $$\mathcal{L}_{\text{KL}} = \text{KL}\!\left(\,\text{softmax}\!\left(\frac{\mathbf{S}_q \mathbf{T}_d^\top}{\tau}\right)\;\Big\|\;\text{softmax}\!\left(\frac{\mathbf{T}_q \mathbf{T}_d^\top}{\tau}\right)\right)$$

Because the loss depends only on $\mathbf{S}_q \mathbf{T}_d^\top$ (dot products), the student can satisfy this loss with any rotation of its embedding space. The student can score well by preserving relative rankings while pointing in completely different directions from the teacher. Result: doc-cosine $\approx 0$ (mean $\approx 0$, $\sigma \approx 0.05$).

3. S8: Internal Alignment Analysis

Central question: S7 showed BiMGA produces better output embeddings. Is this just the output layer being pushed closer to the teacher (trivial), or does BiMGA reshape the model's internal representations (non-trivial)?

Two complementary metrics answer this:

KL Divergence

On attention patterns

Do the layers use similar processing strategies?
(Which tokens attend to which?)

CKA

On hidden representations

Do the layers encode similar information?
(Which examples cluster together?)

3.1 What is KL Divergence (on attention)?

Metric KL divergence measures how different two probability distributions are. Attention weights form probability distributions (they sum to 1 via softmax), so KL naturally applies.

Definition — Attention KL Divergence $$D_{\text{KL}}\!\bigl(S \,\|\, T\bigr) = \sum_{j=1}^{L} S(j)\,\ln\!\frac{S(j)}{T(j)}$$

where $S(j)$ is the student attention weight on token $j$, and $T(j)$ is the teacher attention weight on token $j$, for a single query position across the sequence of length $L$.

PropertyValue / Meaning
Range$[0, \infty)$ — always non-negative
$D_{\text{KL}} = 0$Distributions are identical
SymmetryNot symmetric: $D_{\text{KL}}(S\|T) \neq D_{\text{KL}}(T\|S)$
InterpretationHigher = student attends to tokens differently from teacher
What it tells us: Low KL from a teacher layer means the student is routing information similarly — deciding "which tokens to pay attention to" in a teacher-like way. This measures processing strategy, not just what information ends up encoded.

3.2 How Attention KL is Computed

Implemented in attention_teacher_kl.py → compute_teacher_student_kl():

1
Extract attention matrices from forward passes through both models on all 1,000 test queries.
  • Teacher: $12$ layers $\times$ $12$ heads $\times$ seq_len $\times$ seq_len
  • Student: $4$ layers $\times$ $12$ heads $\times$ seq_len $\times$ seq_len
Both use the same BERT WordPiece tokenizer, ensuring identical sequence lengths. Padding is masked out.
2
Compute per-example KL for every (teacher_layer, student_layer) pair:
Per-example KL computation $$\text{KL}_{i}^{(t_l, s_l)} = \frac{1}{H \cdot L_{\text{seq}}} \sum_{h=1}^{H}\sum_{p=1}^{L_{\text{seq}}} \sum_{j=1}^{L_{\text{seq}}} A_{s}^{(h,p,j)} \ln\!\frac{A_{s}^{(h,p,j)}}{A_{t}^{(h,p,j)}}$$

where $A_s, A_t$ are student/teacher attention weights, $H\!=\!12$ heads, $L_{\text{seq}}$ = actual sequence length (padding excluded), averaged over all heads and all query positions. This yields a $(12, 4)$ matrix per example.

3
Best-matching teacher layer: Since the student has 4 layers and the teacher has 12, we find the closest match per student layer:
Best-matching KL $$\overline{\text{KL}}^{(s_l)} = \min_{t_l \in \{1,\dots,12\}} \; \frac{1}{N}\sum_{i=1}^{N} \text{KL}_{i}^{(t_l, s_l)}$$
4
Overall scalar: Average over student transformer layers (skip embedding layer L0, which has no attention):
Overall Mean KL $$\text{Overall KL} = \frac{1}{4}\sum_{s_l=1}^{4} \overline{\text{KL}}^{(s_l)}$$ 
# From attention_teacher_kl.py
for each example i in 1..1000:
    for ti in 0..11:           # teacher layers
        for si in 0..3:        # student layers
            t_a = teacher_attn[ti][i, :, :sl, :sl]   # (12 heads, sl, sl)
            s_a = student_attn[si][i, :, :sl, :sl]   # (12 heads, sl, sl)
            eps = 1e-10
            kl = sum(s_a * log((s_a+eps)/(t_a+eps)), axis=-1).mean()
            example_kl[ti, si] = kl

mean_kl   = example_kl.mean(axis=0)    # average over examples -> (12, 4)
best_kl   = mean_kl.min(axis=0)        # best teacher match    -> (4,)
overall   = best_kl.mean()             # single scalar

3.5 What is CKA? (and how it differs from cosine similarity)

We already used cosine similarity in S7. Now we need CKA. They sound related but they answer fundamentally different questions.

Cosine Similarity

Compares one vector to one vector.

"Does the student's embedding for this specific example point in the same direction as the teacher's embedding for the same example?"

CKA

Compares a whole layer to a whole layer.

"Does the student layer organize all 1,000 examples the same way the teacher layer does — same clusters, same relative distances, same geometry?"

A concrete example that shows the difference

Imagine a teacher layer and a student layer both process 4 code examples. The teacher produces 2-d vectors; the student produces 3-d vectors (different dimensionalities!):

Can it handle different dimensions?
(teacher: 2-d, student: 3-d)		 No. You cannot compute the cosine between a 2-d vector and a 3-d vector. The dot product is undefined. Yes. CKA compares the $n \times n$ similarity matrices, not the raw vectors. Dimensions cancel out.

(same structure, different orientation)		 Cosine drops toward 0. Each individual vector pair points in a different direction. CKA stays at ~1. The rotation doesn't change which examples are near which.

Used where in our analysis? S7: doc-cosine histograms (per-example alignment of output embeddings in a shared projected space) S8: per-layer teacher-student comparison (can the student's 312-d layers be compared to the teacher's 384-d layers?)
Why we can't use cosine for S8: In S7, we projected both student and teacher embeddings into a shared space before computing cosine — that's why it worked. But for the internal layer analysis (S8), we need to compare raw hidden states across layers with different dimensions (student 312-d vs teacher 384-d) and we want to capture the global structure (not just individual examples). CKA is designed for exactly this.

FAQ: Can't I just average all the cosine similarities?

It seems natural to think: "compute cosine for each of the 1,000 examples, then average — that gives one number per layer, just like CKA." There are two reasons this fails for S8:

Problem 1: Dimensions don't match

Student hidden states are 312-d. Teacher hidden states are 384-d. You cannot compute the dot product of a 312-d vector and a 384-d vector — it's mathematically undefined.

$$\cos(\mathbf{s}_i, \mathbf{t}_i) = \frac{\mathbf{s}_i \cdot \mathbf{t}_i}{\|\mathbf{s}_i\|\|\mathbf{t}_i\|} \quad \longleftarrow \quad \mathbf{s}_i \in \mathbb{R}^{312},\; \mathbf{t}_i \in \mathbb{R}^{384} \quad \Rightarrow \quad \text{dot product undefined!}$$

In S7 this wasn't a problem because both embeddings were projected into a shared space first (via the learned projection head). But internal hidden states at layers L1, L2, L3 have no such shared projection — they live in different-dimensional spaces.

CKA avoids this entirely. It compares the $1000 \times 1000$ similarity matrices ($\mathbf{XX}^\top$ and $\mathbf{YY}^\top$), which are always the same size regardless of the original dimensions.

Problem 2: Average cosine = 0 even when the structure is perfectly preserved

Even if we could match dimensions (e.g., same-sized layers, or using a projection), average cosine would still give the wrong answer in an important case.

Scenario: Imagine the student learns a perfect copy of the teacher's representations, but rotated 90° in the embedding space. Every example is in the right place relative to every other example — the geometry is perfectly preserved.

Teacher (2-d)Student (2-d, rotated 90°)Cosine

Average Cosine = 0.00

"Completely unrelated"

The student preserved the teacher's structure perfectly — Ex 1 and Ex 2 are still close, Ex 3 is still far away — but every individual cosine is 0 because the vectors are all orthogonal. CKA sees through the rotation because it compares the pairwise similarity structure, not the vector directions.

Is this realistic? Yes. Neural network layers routinely develop rotated or reflected versions of the same representation, especially when comparing models with different architectures, different random seeds, or different numbers of layers. A student layer that learns the same information as a teacher layer will almost never produce vectors that point in the same absolute directions — but it will produce vectors with the same relational geometry. CKA is designed to detect exactly this.

Summary

Cosine Similarity (per example) $$\text{cos}(\mathbf{s}_i, \mathbf{t}_i) = \frac{\mathbf{s}_i \cdot \mathbf{t}_i}{\|\mathbf{s}_i\|\;\|\mathbf{t}_i\|}$$

Requires $\mathbf{s}_i$ and $\mathbf{t}_i$ to have the same number of dimensions. Gives one number per example. Measures direction alignment of individual vectors.

CKA (per layer pair) $$\text{CKA}(\mathbf{X}, \mathbf{Y}) = \frac{\|\mathbf{X}^\top \mathbf{Y}\|_F^2}{\|\mathbf{X}^\top \mathbf{X}\|_F \;\cdot\; \|\mathbf{Y}^\top \mathbf{Y}\|_F}$$

$\mathbf{X}$ and $\mathbf{Y}$ can have different numbers of dimensions. Gives one number per layer pair. Measures whether the same examples end up near each other.

Metric Now that we understand the difference, let's look at how CKA actually works step by step.

The core question CKA answers: If I feed the same 1,000 code examples through a teacher layer and a student layer, do examples that are "nearby" in the teacher also end up "nearby" in the student? CKA = 1 means yes, perfectly. CKA = 0 means the two layers arrange examples in completely unrelated ways.

Step-by-step: how it actually works

CKA works by comparing similarity matrices, not individual vectors. Here is the exact procedure, broken into concrete operations:

1
Start with two matrices of representations.

We have $n = 1{,}000$ test examples. A teacher layer produces a vector for each example, and so does a student layer:

  • $\mathbf{X}$: teacher layer output = a table with 1,000 rows (examples) and 384 columns (dimensions)
  • $\mathbf{Y}$: student layer output = a table with 1,000 rows (examples) and 312 columns (dimensions)

The number of columns can differ — that's fine.

2
Center both matrices (subtract column means).

For each dimension, subtract its average across all 1,000 examples. This removes the "where is the cloud of points centered?" information and keeps only "how are points arranged relative to each other?"

$$\mathbf{X} \leftarrow \mathbf{X} - \frac{1}{n}\mathbf{1}\mathbf{1}^\top\mathbf{X}$$

In code: X = X - X.mean(axis=0)

3
Build "similarity matrices" for each layer.

For the teacher, compute how similar every pair of examples is to each other:

Teacher similarity matrix $$\mathbf{K}_X = \mathbf{X}\mathbf{X}^\top \quad \in \mathbb{R}^{1000 \times 1000}$$

Entry $(i,j)$ of $\mathbf{K}_X$ is the dot product of example $i$'s vector with example $j$'s vector in the teacher layer. Large value = the teacher thinks these two examples are similar. Small/negative = dissimilar.

Do the same for the student:

Student similarity matrix $$\mathbf{K}_Y = \mathbf{Y}\mathbf{Y}^\top \quad \in \mathbb{R}^{1000 \times 1000}$$

Now both $\mathbf{K}_X$ and $\mathbf{K}_Y$ are the same size ($1000 \times 1000$) regardless of the original dimensions (384 vs 312). This is how CKA handles different-sized layers.

4
Compare the two similarity matrices.

If the teacher and student organize examples the same way, $\mathbf{K}_X$ and $\mathbf{K}_Y$ will look alike: whenever the teacher says "examples $i$ and $j$ are similar," the student should agree.

CKA measures this agreement as a normalized inner product between the two matrices (treating each $1000 \times 1000$ matrix as a single long vector):

CKA = normalized similarity of the two similarity matrices $$\text{CKA} = \frac{\langle \mathbf{K}_X , \mathbf{K}_Y \rangle}{\|\mathbf{K}_X\| \;\cdot\; \|\mathbf{K}_Y\|}$$

This is essentially the cosine similarity between the two "flattened" similarity matrices. If they agree on which examples are similar to which, the cosine is high (close to 1). If they disagree, it's low (close to 0).

Why the code doesn't build the 1000×1000 matrix

The description above is conceptually correct, but computing a $1000 \times 1000$ matrix is wasteful. The code uses an equivalent algebraic shortcut. Here is the exact code with annotations:

def linear_cka(X, Y):
    # X shape: (1000, 384) — teacher layer
    # Y shape: (1000, 312) — student layer

    X = X - X.mean(axis=0)    # Step 2: center
    Y = Y - Y.mean(axis=0)

    # Step 3-4 shortcut:
    # Instead of building K_X = X @ X.T (1000x1000) and K_Y = Y @ Y.T (1000x1000),
    # the code uses the identity:
    #   ||K_X||_F^2  =  ||X.T @ X||_F^2    (much smaller: 384x384)
    #      =  ||X.T @ Y||_F^2    (384x312 — even smaller)
    #
    # This is just a matrix algebra trick — the result is identical.

    hsic_xy = norm(X.T @ Y, 'fro') ** 2    # =   (cross-term)
    hsic_xx = norm(X.T @ X, 'fro') ** 2    # = ||K_X||^2   (teacher self-similarity)
    hsic_yy = norm(Y.T @ Y, 'fro') ** 2    # = ||K_Y||^2   (student self-similarity)

    return hsic_xy / sqrt(hsic_xx * hsic_yy)
    #      ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    #      = cosine similarity between K_X and K_Y
The algebraic identity:

$\|\mathbf{X}\mathbf{X}^\top\|_F^2 = \|\mathbf{X}^\top\mathbf{X}\|_F^2$ and $\langle \mathbf{X}\mathbf{X}^\top,\,\mathbf{Y}\mathbf{Y}^\top\rangle_F = \|\mathbf{X}^\top\mathbf{Y}\|_F^2$.

Proof sketch: $\|\mathbf{A}\|_F^2 = \text{tr}(\mathbf{A}^\top\mathbf{A})$. Apply this with $\mathbf{A} = \mathbf{X}\mathbf{X}^\top$ and use $\text{tr}(\mathbf{ABCD}) = \text{tr}(\mathbf{BCDA})$ (cyclic trace property) to move terms around. The $n \times n$ matrix products collapse into $d \times d$ matrix products.

So instead of computing two $1000 \times 1000$ matrices, the code computes one $384 \times 312$ matrix (X.T @ Y), one $384 \times 384$ matrix (X.T @ X), and one $312 \times 312$ matrix (Y.T @ Y). Much cheaper.

The complete formula (two equivalent forms)

Form 1 — via similarity matrices (conceptual) $$\text{CKA}(\mathbf{X}, \mathbf{Y}) = \frac{\langle \mathbf{X}\mathbf{X}^\top,\;\mathbf{Y}\mathbf{Y}^\top \rangle_F}{\|\mathbf{X}\mathbf{X}^\top\|_F \;\cdot\; \|\mathbf{Y}\mathbf{Y}^\top\|_F}$$
Form 2 — via cross-covariance (what the code computes) $$\text{CKA}(\mathbf{X}, \mathbf{Y}) = \frac{\|\mathbf{X}^\top \mathbf{Y}\|_F^2}{\|\mathbf{X}^\top \mathbf{X}\|_F \;\cdot\; \|\mathbf{Y}^\top \mathbf{Y}\|_F}$$

where $\|\mathbf{A}\|_F = \sqrt{\sum_{ij} A_{ij}^2}$ is the Frobenius norm (treat the matrix as a long vector and take its length).

CKA vs. KL — complementary views

CKA tells us

Do layers encode similar information?

"Given the same 1,000 inputs, do the teacher and student produce representations where the same examples cluster together?"

Operates on hidden-state vectors (the [CLS] token output).

KL tells us

Do layers use similar processing strategies?

"When processing a token, does the student attend to the same other tokens as the teacher?"

Operates on attention weight distributions (the softmax outputs).

A model could have high CKA (same information encoded) but different KL (different attention routing to get there), or vice versa. Using both gives a fuller picture.

3.6 How CKA is Applied in This Analysis

Now that we know what CKA computes, here is how it is used to compare the 6 student models to the teacher:

1
Extract [CLS] representations at every layer for both student and teacher.

Run all 1,000 test queries through each model with output_hidden_states=True. Take the [CLS] token (first token) hidden state at each layer:

outputs = model(**encoded, output_hidden_states=True)
cls_hidden = [h[:, 0, :] for h in outputs.hidden_states]
# Student: 5 matrices of shape (1000, 312) — embed + 4 transformer layers
# Teacher: 13 matrices of shape (1000, 384) — embed + 12 transformer layers

Each matrix is one "snapshot" of how that layer represents all 1,000 examples. This is the $\mathbf{X}$ or $\mathbf{Y}$ that goes into CKA.

2
Compute CKA for every (teacher layer, student layer) pair.

For one student model, we compute $13 \times 5 = 65$ CKA values — one for each combination of teacher layer and student layer:

cka_matrix = zeros(13, 5)    # rows=teacher layers, cols=student layers
for i in range(13):          # each of the 13 teacher layers
    for j in range(5):       # each of the 5 student layers
        cka_matrix[i, j] = linear_cka(teacher_reps[i], student_reps[j])
        # "How similarly does teacher layer i and student layer j
        #  organize these 1,000 examples?"

This produces a $(13 \times 5)$ heatmap per student model. High values on the diagonal-ish region mean the student's layers map onto the teacher's layers in order.

3
Collapse to one number per student layer by averaging over all 13 teacher layers:
Per-layer CKA (averaged over teacher) $$\overline{\text{CKA}}^{(s_l)} = \frac{1}{13}\sum_{t_l=0}^{12} \text{CKA}\!\bigl(\mathbf{X}^{(t_l)},\;\mathbf{Y}^{(s_l)}\bigr)$$

This gives a single score per student layer: "on average, how much does this student layer's representation agree with the teacher's layers?" We do this for all 6 student models.

4
Subtract the Control baseline to get the CKA gain:
CKA Gain at each layer $$\Delta\text{CKA}^{(s_l)}_{\text{method}} = \overline{\text{CKA}}^{(s_l)}_{\text{method}} - \overline{\text{CKA}}^{(s_l)}_{\text{control}}$$

Positive = this method's student layer is more teacher-aligned than the Control's student layer. This is what Figure (c) plots.

3.8 Why KL and CKA Show Different Per-layer Patterns

At first glance, Figures (b) and (c) seem to contradict each other:

KL per-layer (Fig b)

BiMGA's KL decreases steadily from L1 to L4.

L4 (output) has the lowest KL = most teacher-like.

CKA gain per-layer (Fig c)

BiMGA's CKA gain peaks at L2–L3, then drops.

L4 (output) has the smallest gain.

To understand why, we need to be very concrete about what physical object inside the transformer each metric is looking at.

What happens inside a single transformer layer

A transformer layer is not one operation — it's a pipeline of operations. KL and CKA tap into different stages of this pipeline:

Input hidden states
The [CLS] vector coming in from the previous layer
↓
Attention weights (softmax)
KL looks here. For each token, a probability distribution over all other tokens.
"Which tokens should I pay attention to?"
↓ weighted sum using these weights
Value projection + FFN + residual + LayerNorm
A large chunk of learned parameters that transforms the attended information. KL does not see any of this.
↓
Output hidden states
CKA looks here. The [CLS] vector coming out, which gets passed to the next layer.
"What information did this layer produce?"

This is the key point: between the attention weights (where KL looks) and the output hidden states (where CKA looks), there is a large computation — the value projection ($\mathbf{W}_V$), the weighted sum, the feed-forward network (two linear layers + activation), residual connections, and layer normalisation. All of these have their own learned parameters.

This means:
  • Two layers can attend to the same tokens (identical attention weights → KL = 0) but produce completely different outputs (different CKA), because their value projections and FFN weights differ.
  • Two layers can attend to different tokens (high KL) but produce similar outputs (high CKA), because there are multiple attention strategies that lead to the same result.

Analogy: KL is like comparing which books two students chose to read (their study strategy). CKA is like comparing the essays they wrote (their output). Two students can read the same books but write very different essays. Or read different books but arrive at the same conclusions.

What if we plot both as absolute values?

You asked: if we plot both metrics as absolute values (not CKA gain), do they show the same pattern? No — they show different patterns even in absolute terms. Here they are side by side for BiMGA (Full):

BiMGA (Full): Absolute KL vs Absolute CKA per layer
Blue (left axis): absolute KL from teacher — decreases monotonically (lower = more teacher-like). Green (right axis): absolute CKA with teacher — increases then flattens. The two curves have different shapes because they measure different physical quantities.

The KL line drops steeply and monotonically: each deeper layer's attention patterns are more teacher-like than the previous layer's. The CKA line rises and then plateaus: the output representations become more teacher-like but level off at L3–L4.

Why do the absolute curves have different shapes?

Reason 1: Attention converges faster than representations

Attention weights are small distributions (12 heads, each distributing probability over ~100 tokens). There are relatively few "good" ways to attend for a given task, so models converge to similar attention patterns quickly across layers.

Hidden state representations are huge vectors (312 dimensions encoding information about 1,000 examples). The space of possible representations is vastly larger, and the value/FFN parameters at each layer can reshape them in many ways. So representational alignment builds up more gradually and can plateau or fluctuate.

Reason 2: The residual connection "carries forward" representation but not attention

Each transformer layer has a residual connection: $\text{output} = \text{layer}(x) + x$. This means each layer's output hidden state includes all previous layers' contributions (they accumulate). So CKA at a deep layer partly reflects work done by earlier layers.

Attention weights have no residual connection. Each layer computes its own fresh attention distribution from scratch. So KL at each layer is a clean measurement of just that layer's attention, not a cumulative effect.

This helps explain why CKA can plateau (the cumulative representation converges) while KL keeps dropping (each layer independently becomes more teacher-like).

Reason 3: Same attention + different FFN = different output

Even when BiMGA's L4 attention perfectly matches the teacher's L4 attention (very low KL), the student's L4 hidden state may not match the teacher's L4 hidden state (CKA < 1), because:

  • The student's $\mathbf{W}_V$ (value projection) is $312 \times 312$; the teacher's is $384 \times 384$ — different sizes, different learned values
  • The student's FFN has different weights and a different intermediate dimension
  • The input coming from L3 was already different (because the student is a different model)

So KL can reach near-zero while CKA stays well below 1.

5. Key Takeaways

  1. S7 answers "what": BiMGA produces document embeddings far closer to the teacher ($\cos = 0.88$) than any other method. The key ingredient is bidirectional alignment (query + document), not the margin gate.
  2. S8 answers "where": BiMGA's advantage is concentrated in the middle layers (L2–L3), not the output layer.
    • KL: Attention patterns become progressively more teacher-like with depth
    • CKA: Representational geometry gains peak at middle layers (+0.134 at L3)
  3. The mechanistic story: By aligning both query and document embeddings, BiMGA creates gradient pressure on the shared backbone layers (which process both input types). This forces the middle layers to structurally mirror the teacher, rather than just improving the final output. Output-matching methods (Score, HNP) take a shortcut: better output without internal restructuring.
